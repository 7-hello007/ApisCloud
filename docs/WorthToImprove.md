# 二、需要改进的部分

## 1. 消费性能瓶颈（严重）

**问题：** data-writer 生产速率 500 条/秒 > 消费速率 ~300 条/秒，LAG 持续增长。

**改进方向：**

| 改进 | 效果 |
|---|---|
| Redis 写入合并：7 次 hset → 1 次 hmset | +40% |
| PG 批量写：攒 100 条一次 INSERT | +5-10 倍 |
| data-writer 水平扩展：6 分区 → 6 实例 | +6 倍 |
| simulator 降速：`SIMULATOR_PUBLISH_INTERVAL_MS=2000` | 生产降到 250/秒 |

**代码位置：** `core/services/data-writer/src/redis-writer.ts`、`pg-writer.ts`。

## 2. dispatch-core 无 HTTP 端点

**问题：** `submitTask` 只能代码调用，无法从外部触发。

**改进：** 加 `core/services/dispatch-core/src/server.ts`，暴露 `POST /api/dispatch/task`。

**影响：** `docs/delivery.V1.md` 已列为"已知限制"。

## 3. simulator 不回 ACK

**问题：** `dispatch_commands.status` 一直是 `pending`。

**改进：** simulator 消费 MQTT `commands/{vehicle_id}`，回 ACK 到 `events.commands`，data-writer 更新 status。

**影响：** 计划书 3.4 指令协议的"确认"未实现。

## 4. 限流是内存版，多实例不共享

**改进：** 用 Redis 版限流器。

**代码位置：** `core/libs/src/security/rate-limiter.ts`。

## 5. Prometheus 配置里端口硬编码

**问题：** 改端口要改多处（`docker-compose.infra.yml`、`prometheus.yml`、`.env`）。

**原因：** Prometheus 2.54 不支持 `--config.expand-env`，无法用变量。

**改进：** 升级到 Prometheus 3.x，或用 `file_sd_configs`。

## 6. 文档版本号不规范

**问题：** `architecture.V2.md` 和 `architecture.V1.md` 同时存在。文档规范说"一个功能一个文档，修改时版本递增"，应该删除 V1。

**改进：** 删掉所有被替代的版本（V1 被 V2 替代时，删 V1）。

## 7. 测试覆盖率目标偏低

**问题：** 覆盖率阈值 60%，但很多核心模块实际覆盖率高。

**改进：** 提到 80%，尤其是核心服务。

## 8. CI 不跑 e2e 和集成测试

**问题：** `ci.yml` 只跑单元测试，e2e 和集成测试在本地跑。

**改进：** CI 加 e2e / 集成测试 job。

## 9. 服务健康检查不一致

**问题：**

- simulator / ingest / data-writer / gateway 有独立 HTTP 服务器
- aggregator / dispatch-core 复用 observability 的服务器
- 标准不统一

**改进：** 统一模式：每个服务自己暴露 `/health` 和 `/metrics`。

## 10. 没有 graceful shutdown 的统一管理

**问题：** 每个服务各自处理 SIGTERM，没有统一的 shutdown 编排（如等待处理完当前消息）。

**改进：** 加统一的 shutdown 管理器。

## 11. `verify-e2e.sh` 依赖 simulator 停机

**问题：** 如果 simulator 在跑，LAG 会涨到几万，测试遥测排不上。

**改进：** 脚本里先停 simulator，验证完再重启。

## 12. 缺少速率限制的 Redis 版

**问题：** 内存版限流在单进程有效，多实例部署无效。

**改进：** 用 Redis 计数器实现。

## 13. 没有任务完成/取消的回传路径

**问题：** 外部系统执行完任务后，没有回传机制告诉平台。

**改进：** 加 `events.tasks.status` 主题，接收任务状态变更。

## 14. `docs/README.md` 版本一览需要更新

**问题：** 新增了 `delivery.V1.md` 等，索引可能需要同步更新。

## 15. 前端 dashboard 的"调度任务"panel 无数据

**问题：** `apiscloud_dispatch_tasks_total` 只在 `submitTask` 被调用时递增，当前无外部触发。

**改进：** 配合第 2 项（加 HTTP 端点）。

## 16. 日志未接入 Loki

**问题：** 服务日志用 stdout，Promtail 未接入，Grafana 看不到日志。

**改进：** 加 Promtail 配置，采集 Docker 容器日志到 Loki。

## 17. 时序数据没做数据保留策略

**问题：** `vehicle_telemetry` 表会无限增长。

**改进：** 加数据保留策略（如 30 天），或用 TimescaleDB / ClickHouse。

## 18. `docs/delivery.V1.md` 的"已验证项目"需补充

**问题：** 交付文档里列了 17 项验证通过，但后续又修复了 Prometheus，应该补充。
